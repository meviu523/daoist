## 1.3.0 新增回归

### 九重小境界

六个大境界均验证一重至九重。规则测试覆盖当前重数的修为需求、成功/失败路径、护身符与破境丹、提前停止不退投入，以及九重成功后进入下一大境界一重。化神九重封顶；主线、系统解锁和结局继续使用大境界门槛，避免既有内容因小境界拆分而失去可达性。

40 单自动游玩继续执行，突破判断改用 `G.realmNeed(s)`，验证新增九重结构下主线与守城结局仍可达。

### 炼药师与药鼎

规则测试覆盖未购鼎禁止炼药、只能在长乐集购买/升级药鼎、境界限制、高阶鼎提高成丹率与额外产出概率、灵草/灵力预付、中断不返还、完成一炉才增加熟练度，以及熟练度逐步解锁回春丹、清心散、凝气丹和破境丹。

Chromium 用例不直接篡改角色位置：实际从地图前往长乐集，打开修行面板购买青铜药鼎，再开炉炼制回春丹，检查现金、灵草、炼药次数和熟练度变化。

### 页面隐藏不再自动暂停

`visibilitychange/pagehide/pageshow` 只保存并重置墙钟基准，不新增 `manual` 暂停理由。浏览器隐藏期间不推进模拟；恢复后保持离开前的运行/暂停状态，不补算后台墙钟时间。独立单测同时确认 `GameClock.reset()` 不改变暂停理由。

通用“非页面隐藏的异常长帧”保护仍保留：渲染间隔异常超过 1 秒时进入手动暂停，避免意外批量追赶。

### 到达后清除旧路线

地图只绘制当前选中路线或正在移动的剩余路线，不再用 `lastRoute` 绘制已完成轨迹。Chromium 配送流程在抵达并弹出事件后断言 `.trail-layer path` 已清空；存档中的历史路线字段仍可保留，不影响道路兼容。

## v7 存档兼容

新键为 `night-courier:saves:v7`，识别重建版 v1–v7。旧存档没有 `realmLevel` 时从原大境界一重继续；若 v5/v6 保存的是旧规则下已经开始的大境突破，则按当前大境界九重恢复，并保留旧版整阶修为投入，使目标仍是下一大境界。

旧炼药途中存档没有炼药字段时补一口基础药鼎，仅用于让当前炉合法完成；其他旧档默认未购鼎。v5 的 30→10 分钟充电迁移与 99 地图旧路线兼容继续同时生效。损坏位置、路线、行动类型和未来版本仍被拒绝，不静默修成可加载状态。

## Chromium 25 组检查

核心流程包括：

- 开局显示“凡人一重”，未购鼎时炼药按钮禁用。
- 空闲连续计时、全局暂停、接单真实移动、途中小数坐标与存档恢复。
- 到达目的地后旧路线立即消失；配送事件和奖励只结算一次。
- 面板暂停、手动暂停和 1/3/10 倍速度组合互不串扰。
- 页面隐藏不新增手动暂停，恢复后继续原状态且不补算离开时间。
- 实际前往长乐集买鼎炼药，验证资源与熟练度。
- 320/390 像素全城视图、双指缩放、导航/面板/行动栏无横向溢出。
- 99 地点共享道路 SVG 与拓扑一致；10 分钟充电的 UI、连续进度、暂停和读档一致。
- 新区订单通过实际 UI 接取、移动、途中读档、交付并移除任务点。
- AI 模拟成功、失败回退、迟到响应取消；等待和阅读期间冻结。
- 真实 requestAnimationFrame 探针验证空闲流逝、移动与手动暂停。

测试采用真实构建页面、DOM 和 Chromium 交互，但 localStorage 与 AI fetch 在浏览器脚本中显式模拟；页面隐藏通过可见性事件模拟，不等于真实手机操作系统冻结。
