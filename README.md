# 外卖修仙录 · 项目重建版

**白天送达一份热饭，入夜寻一条自己的仙途。**

这是根据项目对话记录重新实现的单机 Web RPG，版本 **1.8.0**，重建日期 **2026-09-18**。原账号读取返回 `403: Sorry. Your account was suspended`，没有取得旧仓库源码。因此，这是**玩法与需求重建**，不是原始代码、界面和剧情文本的逐字恢复。

已交付完整源代码、可直接打开的单文件版本、本机 AI 代理、自动化测试与恢复说明。无需 GitHub 登录即可运行，不依赖原仓库或在线地图服务。

## 1.8.0：选择后结果与60个配送事件（最新）

选择不再只在日志里留下一句话。每次剧情选择完成后会显示「事件结果」：你选择了什么、发生了什么、实际属性与物品变化；有配送时，现金、外卖币等到账单独显示。按「继续」返回地图，或按「继续剧情」进入下一段主线。阅读期间自动暂停，确认不会再次扣费或发奖。

有耗时的选项先按连续游戏时间执行，完成后才显示结果；刷新或读档保留未确认的结果，已确认的不再弹出。历史记录仍集中在右下角日志。探索、修炼、人物章节与主线选择同样有结果页。

配送事件新增39个，合计 **60个事件、180个选择及对应结果**，涵盖城市生活、邻里互助、夜班骑手和都市修仙奇遇；每个事件至少保留一个无支付障碍选项。22种订单模板是另一类内容，不计入事件数量。

存档升级至v13，已有重建版v1–v12会自动迁移，不需要重开；旧资产、关系、已解锁内容与进行中的行动保留。详见 `docs/TEST_REPORT_1.8.0.md`。

## 1.7.1：出租屋与修车点默认开放（历史）

按最新要求，这两处地点不需要外卖解锁。1.7.0 的 v12 旧档载入时会补齐修车铺，不改时间、余额、人物关系、订单或其他地点记录；升级仍需完成五单。

新旅程默认开放起始出租屋「青藤小屋」和「阿默修车铺」。其他地点先随外卖订单出现在地图上；第一次成功送达并完成配送事件选择后，永久记录为已解锁。仅查看订单、接单、途中经过、停止或取消配送都不解锁；耗时选项必须实际完成，午夜房租破产仍先于同刻交付，不提前解锁或发奖。没有事件的配送在实际送达结算时直接解锁。

医馆、书店、长乐集、听雨观、沿江公园及另外两处住处，发现后才显示常驻入口；普通住宅配送点即使已送达过，仍只在有订单时显示，避免地图拥挤。解锁通知仅记录在右下角日志，不新增弹窗。首次发现不额外送现金、外卖币或物品。

保留原有前两个近单名额；从第三个补单名额起，若地图及在途订单没有未知服务地点，会优先补入最近的未知服务地点，避免关键设施只能漫长等待随机出现。其余订单继续按现有规则刷新，未发现地点也可正常接单并沿原道路配送，不添加取餐流程、瞬移或送达时限。

地点与玩法门槛分别校验。未解锁地点不能通过赶路、羁绊拜访、搬家、修车、治疗、探索、商店或拍卖快捷入口绕过；随机结识人物不会直接授予其所在地。发现长乐集也不会提前开放炼药、拍卖或未获得的丹方。保留原地休息、充电、步行、回当前住处睡眠与受伤救助，救助到医馆不算完成配送。

应用1.7.0、存档v12，以 `unlockedPlaces` 保存地点。旧版v1–v11原本已开放的固定地点继续保留，不回收既有设施；旧非配送行程与当前住处也保持可继续，未结算的普通地址订单不推断为已经送达。新格式读档校验地点列表、当前住处、进行中的当地行动及拍卖权限；重复读取不重复奖励，新旧存档相互隔离。新开存档可完整体验从小屋开始、靠外卖逐一发现城市的过程。

## 1.6.0：万宝拍卖场（历史）

万宝拍卖场设在长乐集二楼，沿用原地图节点与真实道路移动，不增加瞬移。已开放炼药且累计完成 10 单配送后，导航栏出现「拍卖」，长乐集也出现服务入口；未达条件时隐藏，直接调用竞拍指令同样会被拒绝。

每日 18:00–24:00 开拍，白天到场可提前查看当日三件拍品。药材成包、成品丹药与当前境界可用的药鼎进入图录；玩家尚未买过第一口鼎或当前境界药鼎已收齐时，第三件改为另一包药材。拍卖不出售丹方，不改变剧情、羁绊、商店各 36 张的专属规则。药鼎竞得后加入收藏，不自动换鼎；第一口药鼎仍须在长乐集炼药摊购买。

当日第一次查看图录时，固定拍品和三位匿名竞拍者的预算；重开面板和读档不换货、不重抽对手。对手是拍卖背景角色，不自动加入羁绊。药材参考价沿用商店售价，药鼎参考价沿用购鼎价格；成品丹药参考价根据品类、阶数与数量计算。起拍价为参考价的 65% 向上取整到 5 元，每口为参考价的 8% 向上取整到 5 元且至少 5 元；这不保证最终买到的价格低于商店。

每次可「加一口」或「加三口」，一轮竞价持续 5 个游戏分钟。出价先将全额现金转为冻结款，暂停、倍率与其他行动共用同一时钟；提交后本轮不可中断，不允许同时出价两件拍品。对手超价时全额返还冻结款，再选择继续加价或免费放弃；无人继续竞争时才落槌，冻结款转货款并发放拍品，不再重复扣款。每轮只在真正完成时结算，没有按帧随机报价。距散场不足一轮时禁止新出价；最后一轮被超价则退款并结束该拍品。

冻结款不是可用现金，不能用于支付房租。第 7、14、21… 日午夜依然先扣租，余额不足会先结束游戏，不能预支同刻拍卖退款或成交物品。资金上限内预留退款空间，正在竞拍的物品也预留库存容量。历史竞价与成交记录只写右下角日志；面板只显示当前图录、状态、报价和累计竞得数量。

存档升为 v11，保存图录、对手预算、当前轮次、冻结款与成交状态；v10 及更早存档显式迁移为空拍卖记录，保留原有玩法、物品和在途行动。进行中或待选竞拍重载后可继续，已成交拍品不重发；缺失冻结款关联、非法物品或轮次会拒绝读取并保留损坏存档，不静默清空吞款。新旧存档各自保存拍卖数据，读档默认暂停，无关闭页面后的离线拍卖。

10 单、每日三件、开拍时间、五分钟轮次及报价比例是本轮采用的配置数值，不是用户指定的固定数值。经典和 AI 模式共用确定性拍卖规则，AI 不生成竞价金额或结算奖励。

## 1.4.2：丹方获取途径差异化（历史）

108 张丹方分成互不混售的三类：剧情、羁绊、商店各 36 张。每类丹药在三类渠道中各有三张不同配伍的丹方；这是本次采用的内容分配，不是丹药阶数。丹方仍然只在获得之后显示具体名称、产物、配伍和要求。

剧情丹方分六批、每批六张：领取首个主线委托「第一份人间烟火」奖励，以及完成「地图上多出来的一条线」「城市的背面」「每个人都是一个阵点」「系统第一次拒绝回答」「万家灯火，不属于任何人」五段主线选择。看到待选剧情或仅达到境界不算完成；有耗时的选择必须实际结算才发方。

六位 NPC 各传六张，分别在完成第 1 / 2 / 4 章且信任达到 3 / 9 / 20 时授予两张。必须已经结识；友情和情感路线都能取得，不强制恋爱。林晚传回春、血元配伍；陈默传锻体、玉髓；沈青禾传凝气、灵元；陆听雨传破境、聚元；周野传清心、养元；苏砚传回灵、三元。羁绊页只显示已结识人物的传方进度和下一阶段条件，不预告未得丹方的名字。

长乐集仅出售商店类未知残卷：当前境界允许且尚未获得的商店丹方中随机一本，不重复，不消耗时间。价钱仍为 ¥45 + 大境界索引 × ¥30。买齐不会越过剧情或羁绊专属限制，售罄或现金不足不会扣款。普通探索不再直接随机掉落丹方，继续提供药材和奇遇。

获得后永久保留；信任下降不会收回丹方。存档格式保持 v9，旧档已获得的全部丹方不撤销；已经完成的主线和羁绊在读档时补领尚未取得的奖励，但待选或进行中的剧情不提前补领。不会重复发放或在界面层修改存档。获得丹方不等于可以开炉：熟练度、境界、药鼎、药材和灵力要求仍独立校验，丹药一至九阶仍由药鼎和炼药师共同决定。

## 1.4.1：丹方需要获得（历史）

丹方不再随炼药熟练度或境界自动出现。新存档没有任何丹方；只有真正获得的丹方才会显示名称、产物、药材配伍、火候和要求。未获得丹方在界面中完全隐藏，不能通过直接构造丹方 ID 绕过规则开炉。

丹方主要通过两种途径获得：在长乐集购入一卷**未知丹方残卷**，购买前不会显示具体是哪张丹方；或在月渡公园、听雨观探索时发现残页。获得后丹方永久写入存档。获得只是“拥有配方”，实际炼制仍需满足对应熟练度、境界、最低药鼎阶位、药材和灵力要求。

存档提升为 `schemaVersion: 9`。v8 旧存档当时按境界与熟练度已经可以使用的丹方，会迁移为“已获得”，进行中的炼药丹方也会强制保留，避免升级后丢失已有能力。

## 1.4.0：炼药体系扩展（历史）

炼药体系扩展为 **64 种药材、108 张丹方、24 种药鼎**。24 种药鼎统一分为一至九阶，同阶器型分别偏向成丹率、额外产出与成色；玩家可在长乐集购买并切换已经拥有的药鼎。64 种药材同样按阶位与境界逐步开放，可在长乐集购买，也可通过月渡公园、听雨观探索获得。

丹方与丹药现在严格分离。108 张丹方分别保存产物、药材配伍、灵力消耗、火候时间、复杂度、熟练度/境界门槛和最低药鼎阶位；丹方本身**不固定丹药阶数**。炼成的丹药独立分为一至九阶，成品阶数由当前药鼎阶位与炼药师水平共同限制，悟性继续影响成丹率。破境丹也保留阶位：突破时自动使用玩家选择下的最高阶破境丹，高阶丹提供更高成功率加成。

存档提升为 `schemaVersion: 8`。旧 v7 的三档药鼎会显式映射到新 24 鼎体系中的对应器型；旧回春丹、清心散、凝气丹、破境丹按一阶成品继续保留，新增库存字段补 0，不要求重开存档。

## 1.3.4：时间倍率选择框保持稳定（历史）

修复世界时间推进到订单刷新、昼夜/日期边界等需要完整界面刷新的节点时，顶部时间倍率选择框被重建、从而在操作中突然关闭的问题。顶部状态栏现在只在首次进入游戏时创建；后续世界刷新仅更新玩家信息、货币、天气、资源与时间文本，`#time-speed` 和整个 `.time-controls` 节点保持不变，因此正在聚焦或展开的原生选择框不会被刷新打断。

浏览器回归会把倍率设为 10 倍并聚焦选择框，推进到 15 分钟订单刷新边界，再断言选择框和时间控件容器仍是同一 DOM 节点、焦点仍在选择框且倍率仍为 10 倍。存档格式不变。

## 1.3.3：修复配送点进度环对齐

修复部分浏览器/缩放状态下配送点图标与圆形进度环错位的问题。进度环现在使用 SVG 自身的 `rotate(-90 0 0)`，明确以配送点局部坐标原点为旋转中心，不再依赖 CSS 的 `transform-origin:center`。浏览器测试新增点心与圆环中心坐标重合断言。

## 1.3.2：订单消失时间与地图进度环

配送订单不再有“送达时限”。地图上的未接订单只保留**消失时间**：到点前可以接单，接下后订单立即锁定，途中停止、改道、处理配送事件都不会因为耗时而失效，也不会因晚送降低现金、外卖币或口碑奖励。为兼容现有 v7 存档，订单内部仍沿用 `expiresAt` 字段名，但它现在只表示“未接订单从地图消失的游戏时间”。

地图配送点新增圆形剩余进度环，环形随游戏时间连续缩短；新订单出现时淡入弹出，订单自然消失、取消或配送完成后缩小淡出。动画只改变视觉，不参与规则判定；系统“减少动态效果”偏好下会自动跳过动画。普通地点和已接订单仍保持可点击，已接订单不显示消失倒计时。

本次不改变存档结构，继续使用 `schemaVersion: 7`。旧档中的待接订单按原 `expiresAt` 作为一次性的地图消失时间继续兼容；旧档已经接下的订单会忽略该时间。PR #10 完整 CI 已验证 `npm test` 183/183、Chromium 29/29，并通过语法检查与静态构建。

## 1.3.1：110 地点与后台持续计时

## 开始游玩

### 方式一：直接打开离线版

用浏览器打开 `dist/index.html`，点击“开启新旅程”，输入名字并选择**经典剧情**。界面、地图、规则和经典剧情都在这一个文件里；不需要安装依赖。

**长期存档建议使用下面的本机服务。** 浏览器直接打开 `file:` 文件时，localStorage 的行为没有统一保证，不同浏览器可能不同。程序会在保存失败时提示，并保留当前页面中的可导出进度。关闭页面前请导出 JSON 存档。[1]

### 方式二：本机服务（推荐）

准备 **Node.js 22.16.0 或以上版本**。在项目根目录运行：

```sh
npm start
```

然后在浏览器打开：

```text
http://127.0.0.1:8787
```

Windows 也可双击根目录的 `开始游戏.bat`。本项目没有 npm 运行时依赖，**不需要先执行 `npm install`**。关闭终端或按 `Ctrl+C` 会停止本机服务；游戏存档仍位于浏览器中。

请固定使用同一浏览器、同一个地址和端口游玩。不同来源的浏览器存储彼此隔离；更换入口前先导出，随后再导入。[1]

## 第一段旅程

创建经典存档后，从青藤小屋出发。选择地图上的金色订单标记，检查消耗后“接单并配送”。第一单会触发系统绑定事件；**做出事件选择后才结算配送奖励**，不要在事件完成前把报酬当作已到账。

现金用来支付房租、充电、修车与升级；外卖币直接在左下角“系统”兑换物品。住处可在“歇息”中更换：低租住处恢复较少，高租住处恢复更完整。每 7 天必须支付当前住处完整房租，现金不足则本局结束。体力不足可在“歇息”原地恢复，也可回小屋睡觉。没有电时，在“座驾”切换步行；不要强行接下无法完成的行程。

晚上进入“修行”收益更高。六个大境界都分为一重至九重；达到当前小境界门槛后突破到下一重，九重成功后才进入下一大境界一重。原地修炼无需赶路，前往听雨观则有额外灵地收益。炼药要先去长乐集购买并选择药鼎。丹方不会自动解锁：长乐集只能购入不显示具体内容的未知残卷，探索也可能发现丹方；只有获得后才会在炼药页显示。获得丹方后仍要满足熟练度、境界、鼎阶、药材和灵力条件。完成一炉才累计熟练度；丹药阶数由药鼎和炼药师共同决定。拜访人物会先计算去其所在地的距离，再加交谈本身的时间。

主线不会在开局一次性倾倒设定：完成若干配送、进入更高境界、结识人物后，会依次触发“街脉显形 → 城市背面 → 灯火阵点 → 系统质疑 → 系统真相”。高阶系统兑换也随境界解锁，让成长和剧情同步展开。

地图支持单指/鼠标拖动、滚轮或双指缩放；`+`、`−` 缩放，定位按钮回到玩家，全图按钮查看整座城市。地图标记可用键盘聚焦后按 Enter，方向键可以平移地图。

## 连续时间与操作

新游戏默认开始运行；读取存档默认暂停，点击顶部“继续”后恢复。正常现实 1 秒 = 游戏 1 分钟，时间旁可切换 1 / 3 / 10 倍。运行时不操作也会计时，未接订单会按地图消失时间移除，房租也会到期。

点击地图地点或订单查看路线，再确认出发。人物沿道路移动，消耗随实际路程扣除。地图底部行动栏显示剩余路程、预计时长与进度。“停止”只停下当前行动，世界时间继续；已经接下的配送没有送达时限，不会因为停下而失效。顶部“暂停”才冻结整个游戏。暂停时仍可查看地图、面板、安排行动和进行零耗时系统兑换。

面板和剧情自动暂停，关闭后恢复打开前的状态；不会解除手动暂停。切换标签页或应用不再自动暂停；后台按当前倍率计时，延迟回调分批推进，遇到剧情立即停下。手动暂停不会被返回页面解除。关闭/重载页面不补算离线时间。睡眠、充电、休息、修炼按进度恢复/增长；炼药和突破开始时扣投入，中断不退，突破失败会退回约 75% 本次需求修为。耗时剧情选择提交后不可取消。

搬家到达后住处才生效。第 7、14、21… 日零点房租优先于同刻交付和入住结算；现金不足立即结束，不能用尚未送达的报酬垫付。

## 存档、备份与迁移

自动存档保存的是**游戏状态**，不是源码备份。请同时保存本项目 ZIP 与导出的存档 JSON。

开始页可以导出全部存档、导入存档，或导出/删除单份存档；游戏中点击顶部玩家信息可以导出当前存档。导入总是建立新副本，不覆盖同名、同 ID 的既有记录。删除和恢复自动备份需要确认。

当前格式是 `schemaVersion: 9`。迁移逻辑支持能够识别的重建版 v1–v9 字段；新存储键不存在时自动迁移 v8/v7/v6/v5/v4/v3 本机存档。地图与 10 分钟充电规则继续兼容；旧档没有小境界字段时从原大境界一重继续。v7 的三档旧药鼎仍映射到新 24 鼎体系，旧丹药按一阶保留；v8 旧档当时按境界和熟练度已经能使用的丹方迁移为已获得，进行中的炼药丹方也强制保留。进行中行动保留小数时间与道路坐标，不重复扣费或发奖。**没有验证过原仓库旧存档格式**，不能保证旧存档可直接导入。不要为了通过校验，简单修改未知旧存档的版本号。

本地存储禁止写入或空间不足时，界面会提示“未保存”；页面内仍可继续并导出。自动备份只保留前一份写入状态，不是永久历史。多人共享设备、清理站点数据或更换浏览器前请先导出。

## AI 剧情（可选）

经典剧情不需要任何密钥。AI 模式需要**本机 Node 服务**以及你自行配置的兼容 Chat Completions JSON 接口；本次未连接真实模型服务，测试使用模拟上游响应。

将 `.env.example` 复制为 `.env`，填写：

```dotenv
HOST=127.0.0.1
PORT=8787
AI_API_URL=https://your-provider.example/v1/chat/completions
AI_API_KEY=replace-with-your-own-key
AI_MODEL=replace-with-your-model-name
AI_ALLOW_LOCAL_HTTP=false
```

上面 `.example` 地址只是格式示例，不能直接调用。`AI_API_URL` 必须是**完整接口地址**，不是只有主机名；它需要接受 `messages`、`response_format: {"type":"json_object"}` 和 `max_tokens`，并在 `choices[0].message.content` 返回 JSON 文本。不同提供方/模型的参数兼容性可能不同，接入后需要实测。

修改后重新启动 `npm start`。在开始页创建 AI 模式的新存档；已有 AI 存档重新打开页面后也会读取新的服务状态。已创建的经典存档不会改成 AI 存档。

AI 生成用于随机配送/探索/修炼事件及人物日常交谈；系统初次绑定、人物关键章节和主线节点保留经典内容。每次请求只发送角色名、部分游戏状态、所在地点、当前事件素材和最近三条日志文本。它可能产生提供方的接口费用，未配置时不会代为开通任何服务。

密钥仅由本机服务端读取，不写进前端、存档或构建产物；`.env` 已加入忽略规则。不要把密钥放进浏览器代码或提交到仓库。[2]

只接受白名单 JSON 效果并限制数值。AI 不能执行代码、切换模式、直接设置境界/地点，不能绕过主线要求。接口超时、报错、返回非法内容时，仍有经典三选项可选；等待期间也能直接选经典选项。迟到的 AI 回包不会覆盖已经结算的事件。

默认仅监听本机地址。当前服务**不是生产级多人后端**，没有账户体系、身份认证或云存档；不要把带真实密钥的接口直接暴露到公网。
